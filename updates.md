## 2. Module Inputs, Outputs & Current Status

### A. Ingestion Module (`graph/ingestion`)
- **Inputs**: PDF research paper files (e.g., `data/papers/1-Attention Is All You Need.pdf`).
- **Outputs**: A clean `Document` object with attributes:
  - `text` / `cleaned_text` (extracted clean string content)
  - `metadata` (extracted PDF metadata properties)
- **Status**: Fully functional. Verified using `tests/test_ingestion.py`.

### B. Extraction Module (`graph/extraction`)
- **Inputs**: `Document` object.
- **Outputs**: `ExtractionResult` object containing:
  - `paper` (`Paper` metadata model)
  - `entities` (list of `Entity` models with `id`, `name`, `type`, `description`)
  - `relationships` (list of `Relationship` models with `source`, `relationship`, `target`, `confidence`)
- **Status**: Fully functional. LLM parses entities and filters them against the `schema.py` ontology.

### C. Graph Builder Module (`graph/graph_builder`)
- **Inputs**: `ExtractionResult` object.
- **Outputs**: A NetworkX `MultiDiGraph` saved in three formats:
  1. **GraphML**: Saved to `data/graphs/attention.graphml` (NetworkX XML graph format).
  2. **JSON**: Saved to `data/graphs/attention.json` (Structured node/edge dictionary).
  3. **HTML Visual Network**: Saved to `tests/graph.html` (Interactive pyvis network visualization).
- **Status**: Fully functional. Incorporates automatic paper linking (connecting the `Paper` node to all `Author` nodes via `AUTHORED` and `Method` nodes via `PROPOSES`).

### D. Retriever Module (`graph/retriever.py`)
- **Inputs**: Natural language user query string (e.g., *"Who wrote the Attention paper?"*).
- **Outputs**: Formatted Markdown string of **Relational Context** containing matched entities (including types/descriptions) and their direct connections (edges) retrieved from the graph.
- **Status**: Fully functional. Integrates:
  - Plural/singular keyword stemming (e.g., matching `"datasets"` to `"dataset"`).
  - Verb/relationship type matching (e.g., query keyword `"propose"` scores and retrieves nodes connected by `PROPOSES` edges).

### E. GraphRAG Orchestration (`graph/rag.py`)
- **Inputs**: User query string.
- **Outputs**: Complete natural language answer generated by Gemini using only the retrieved relational context.
- **Status**: Fully functional. Integrates retrieval and generation end-to-end.

## 3. Log of Recent Changes

### 1. API Consolidation
- Restored the instance-based API for `GraphSerializer` in `graph/graph_builder/serializer.py` to ensure compatibility with `test_graph_builder.py` and `visualize_graph_builder.py`.
- Fixed imports and constructor methods in `GraphManager` to correctly use `NodeFactory` and `EdgeFactory`.

### 2. Serialization & Robustness Fixes
- Added filtering in `GraphBuilder`, `NodeFactory`, and `EdgeFactory` to strip `None` values from node/edge attributes, resolving a NetworkX XML GraphML writer exception (`NoneType as data values`).
- Replaced the failing pyvis `net.show("graph.html")` call in `visualize_graph_builder.py` with `net.write_html("tests/graph.html")` to avoid notebook-mode template errors and direct output to the `tests/` folder as requested.

### 3. Relationship Processing Bug Fix
- Updated `ExtractionParser` to normalize relationship `source` and `target` names to generated ID format (e.g., `ashish_vaswani` instead of `"Ashish Vaswani"`) during parsing. This prevents relationships from being silently dropped by the validator due to key mismatches.
- Updated the prompt in `llm/prompts.py` to force the LLM to output relationships mapping exactly to extracted entity names.

### 4. GraphRAG & Verification Script
- Implemented the `GraphRetriever` class (`graph/retriever.py`) and the `GraphRAG` orchestration pipeline (`graph/rag.py`).
- Added a full integration test script `tests/test_graph_rag.py` to verify ingestion, extraction, graph building, relational context retrieval, and context-based query answering.
