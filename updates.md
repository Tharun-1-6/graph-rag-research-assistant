## 2. Module Inputs, Outputs & Current Status

### A. Ingestion Module (`graph/ingestion`)
- **Inputs**: PDF research paper files.
- **Outputs**: A clean `Document` object with text and metadata.
- **Status**: Fully functional.

### B. Extraction Module (`graph/extraction`)
- **Inputs**: `Document` object.
- **Outputs**: `ExtractionResult` object containing `Paper` metadata, `Entity` list, and `Relationship` list.
- **Status**: Fully functional.

### C. Graph Builder Module (`graph/graph_builder`)
- **Inputs**: `ExtractionResult` object.
- **Outputs**: NetworkX `MultiDiGraph` serialized to GraphML, JSON, and Pyvis HTML visualization (`tests/graph.html`).
- **Status**: Fully functional.

### D. Upgraded Retrieval Engine (`graph/retrieval`)
- **Inputs**: Natural language user query string.
- **Outputs**: A structured `RetrievalResult` containing:
  - `context`: Structured, deterministic, sorted Markdown context block within node/edge/character budgets.
  - `parsed_query`: Candidate entities, keywords, verbs, and noun phrases.
  - `query_intent`: Rule-based intent detection (e.g. `AUTHOR_QUERY`, `METHOD_QUERY`, `DATASET_QUERY`).
  - `retrieval_plan`: Target node types, allowed relationships, search depth, and node limits.
  - `matched_nodes` & `ranked_nodes`: Normalized matching & ranking scores (0.0 to 1.0) using structural and semantic heuristics.
  - `statistics`: Map of nodes, edges, seeds, and character size of returned context.
  - `retrieval_trace`: Comprehensive debugging execution trace log containing parsed targets, plans, seeds, best paths, and stats.
- **Status**: **Upgraded (v3)**. Fully functional. Implements 14 advanced precision optimizations including adaptive depths, hierarchical matches, priority relationships, paper-centric traversal hubs, duplicate path elimination, path-based ranking, connected component pruning, and trace logging.

### E. GraphRAG Orchestration (`graph/rag.py`)
- **Inputs**: User query string.
- **Outputs**: Complete natural language answer generated by Gemini using the retrieved context.
- **Status**: Fully functional.

## 3. Log of Recent Changes (Version 3 Upgrades)

1. **Hierarchical Matching & Pre-Filtering**: Updated `matcher.py` to pre-filter search candidates by active intent node types, and execute query matching hierarchically (stopping early when exact/alias matches are found). Restrained category matching to prevent query floods.
2. **Adaptive Traversal Budgets**: Refactored `planner.py` to assign traversal depths dynamically based on intent complexity (ranging from depth 1 for authors to depth 3 for explanations/comparisons).
3. **Edge Expansion Priority**: Updated `traverser.py` to prioritize high-priority semantic relationships (`AUTHORED`, `PROPOSES`, etc.) first, visiting low-priority `RELATED_TO` edges last and strictly within the node budget.
4. **Paper-Centric Hubs**: Configured the traverser to prioritize traveling through `Paper` nodes first to utilize them as central knowledge hubs.
5. **Path Scoring & Deduplication**: Replaced independent ranking in `ranker.py` with path scoring that accounts for distance penalties, edge weights, and exact matches. Deduplicated multiple paths reaching the same target.
6. **Connected Component Pruning**: Configured component detection in `ranker.py` to retain only the highest scoring component (unless a comparison query is executed).
7. **Intent-Aware Section Formatting**: Configured `formatter.py` to hide irrelevant or empty markdown sections based on intent.
8. **Evidence Traces & Diversity Budgets**: Added category diversity budgets to formatting logic to prevent single types from dominating, and implemented debug-mode evidence logging displaying score, depth, and paths.
9. **Trace Logging & Evaluator**: Created `evaluator.py` to calculate precision, recall, average path hops, and latency, returning them alongside execution traces in `GraphRetriever.retrieve()`.
10. **Validation Test suite**: Updated `tests/test_retrieval_engine.py` to benchmark all 12 query pathways and budget constraints. All tests completed successfully.
